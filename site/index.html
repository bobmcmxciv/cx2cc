cx2cc

把 ChatGPT 订阅里的 Codex 模型包装成 Anthropic 与 OpenAI 两种协议的 API。 Claude Code、Codex CLI、cc-switch、Chatbox、OpenAI SDK 都能直接接入； 公网入口按个人 API Key 鉴权与限额，每一次调用都有审计记录。

接入

每位使用者向管理员申请一把个人 API Key（形如 sk-cx2cc-…）， 所有客户端都用这一把。入口地址：

https://cx2cc.bobmcmxciv.xin/api          Anthropic 协议（Claude Code）
https://cx2cc.bobmcmxciv.xin/api/v1       OpenAI 协议（Codex CLI、SDK、Chatbox）

Claude Code

写进 ~/.claude/settings.json 的 env。这个文件的优先级高于终端里的环境变量； 以前配过 ANTHROPIC_API_KEY 的请删掉，它会盖过下面的 Token。

{
  "env": {
    "ANTHROPIC_BASE_URL": "https://cx2cc.bobmcmxciv.xin/api",
    "ANTHROPIC_AUTH_TOKEN": "sk-cx2cc-你的Key",
    "ANTHROPIC_MODEL": "gpt-6.1-sol"
  }
}

ANTHROPIC_MODEL 可以不写：Claude Code 自带的 opus / sonnet / haiku 名称都会落到服务端的默认模型。 可选模型见 GET /api/v1/models。改完重启 Claude Code 才生效。

Codex CLI

~/.codex/config.toml。Key 放在 http_headers 里，新版 Codex 不会从 auth.json 回填第三方供应商的 Key。

model = "gpt-6.1-sol"
model_provider = "cx2cc"

[model_providers.cx2cc]
name = "cx2cc"
base_url = "https://cx2cc.bobmcmxciv.xin/api/v1"
wire_api = "responses"

[model_providers.cx2cc.http_headers]
Authorization = "Bearer sk-cx2cc-你的Key"

Codex 的网页搜索（包括 0.158 起的独立搜索）直接可用；要实时联网，在顶层加 web_search = "live"。

OpenAI 协议客户端

OpenAI SDK、Chatbox 以及其他支持自定义 OpenAI 地址的工具：Base URL 填 https://cx2cc.bobmcmxciv.xin/api/v1，API Key 填个人 Key，模型名从 /api/v1/models 里选。入口处理了跨域预检，Chatbox 网页版和手机端也能直接用。

cc-switch 与出图

  • cc-switch 的用量查询：自定义脚本请求 {{baseUrl}}/usage，请求头 x-api-key: {{apiKey}}，就能在供应商卡片上看到订阅的剩余额度。
  • gpt-image 出图 skill 复用 Claude Code 已有的 ANTHROPIC_BASE_URL 和 ANTHROPIC_AUTH_TOKEN，调用 /v1/images/generations 与 /v1/images/edits。
  • Key 需要有对应的权限范围：出图要「图片」，用量查询要「额度」。

公网入口与网关

cx2cc-gateway 只管「谁在用、用了多少、能不能用」，不改动请求内容。 它核验个人 Key 之后换成内部凭据转发，后面的 cx2cc 与 codex-bridge 不需要知道有多少使用者。

每人一把 Key按别名和使用人管理。明文只在创建或轮换时显示一次，服务端只保存哈希。
权限范围对话、图片、额度查询、账号池四类，逐把勾选。账号池含订阅邮箱，只授予管理员指定的 Key；普通 Key 查额度时，返回里的邮箱和账号 ID 会被去掉。
模型白名单可限定一把 Key 能用的模型。请求名和别名解析后的实际模型任一命中即放行，不写模型时按默认模型判断。
限流与额度每分钟请求数、并发数、每日加权额度、近 7 日加权额度。超出时返回 429 并附 Retry-After。
Key 生命周期设置有效期；随时停用、启用；轮换时旧值可保留 0–168 小时宽限；吊销后立即失效且不可恢复。
逐次调用审计时间、Key、来源 IP、客户端、路由、请求模型与实际模型、输入 / 缓存 / 输出 token、加权用量、首字节与总耗时、会话 ID、失败原因。提示词与回复内容不落盘。
操作日志登录与登录失败、Key 的创建 / 修改 / 停用 / 轮换 / 吊销、账号与设置变更、审计导出，全部记下操作人和 IP。
管理控制台用量概览、按 Key / 使用人 / 模型汇总、每日与每小时趋势、调用查询与 CSV 导出、上游模型目录与账号池状态。
角色分权管理员；Key 管理员可以创建 Key，只看得到、管得了自己创建的那些；审计员只读全部记录。持 Key 的人可以用自己的 Key 登录，只看这一把的用量。
流式透传SSE 逐块转发，不攒包；上游中途断流时补发一条错误事件，客户端能看到原因并重试。每个响应带 X-Cx2cc-Request-Id，可凭它查到对应的审计记录。
加权用量口径(输入 − 缓存) × 1 + 缓存 × 0.1 + 输出 × 8，与订阅额度的计量方式一致，限额和排行都按它算，权重可在设置里调整。
浏览器客户端入口统一处理 CORS 预检，网页和 WebView 形态的客户端不需要额外代理。长推理最长允许 15 分钟无输出，请求体上限 64 MB。

cx2cc：协议转换层

cx2cc 让只会说 Anthropic 协议的 Claude Code 用上 OpenAI 协议的模型，同时给 OpenAI 协议的客户端开一条原样透传的路。

Anthropic Messages 兼容system、文本、图片、工具定义、tool_use / tool_result、tool_choice、停止序列，流式与非流式事件完整转换，覆盖 Claude Code 的日常流程。
网页搜索Claude Code 的 WebSearch 映射到上游原生的 web_search，返回带链接与标题的搜索结果块；allowed_domains 转成上游的域名过滤。
OpenAI 协议透传Chat Completions、Responses（Codex CLI）、独立搜索（Codex 0.158+）、图片生成与参考图编辑（最多 16 张）原样转发，共用同一套上游与缓存策略。
模型解析去掉 [1m] 之类的窗口后缀，按别名表改写；Claude 自带的模型名落到默认模型；不认识的模型名直接返回 400，不会悄悄换成别的模型。/v1/models 标出每个名字实际由哪个模型服务。
如实上报模型响应里写的是实际服务请求的模型，而不是回显客户端请求的名字，用量统计不会被 claude-opus 之类的名字带偏。
会话级缓存亲和按会话生成稳定的 prompt_cache_key，同一会话各轮落在同一缓存节点，逐轮命中率在真实会话上从约 13% 提到约 99%；缓存读取量作为 cache_read_input_tokens 回报。
上下文用量估算流式开始时，按本会话已测得的 token 与字符比例估算提示词大小，每轮用真实值校准。Claude Code 的上下文用量条因此有数，不再显示 0%。
回复风格约定在 system prompt 末尾追加一段写作约定：先说结论、成段叙述、不给每个工具调用配旁白。只追加不前置，前缀缓存不受影响；可关闭或替换成自己的文本。
额度与账号池透传/usage 供 cc-switch 和 HAPI 显示订阅余量，/accounts 显示账号池里谁在服务、谁在冷却。
断流与缓存诊断上游中途断开时给客户端发明确的错误事件；每个请求记录会话 key、工具数与分段内容哈希，命中率下降时能分清是提示词变了还是上游丢了缓存。
多平台发布Windows EXE（带图形启动器）、macOS arm64 与 x86_64 原生包、源码运行；发布流水线带冒烟测试、文件白名单、SHA-256 校验和全历史密钥扫描。

codex-bridge：上游适配与账号池

Codex 后端只接受 ChatGPT 登录凭据和 Responses 协议。codex-bridge 把这一层包起来，让上面的 cx2cc 像调用普通 OpenAI 兼容接口一样调用它。 代码开源在 github.com/bobmcmxciv/codex-bridge， 单独使用也可以：任何能填 OpenAI 兼容地址的客户端都能直接接它。

ChatGPT 登录直连使用 Codex CLI 的 ChatGPT OAuth 凭据，不需要 OpenAI API Key；访问令牌过期前约 5 分钟自动刷新并写回。
协议适配Chat Completions 转 Codex Responses，工具调用、图片输入、推理强度和流式输出都支持；Responses 请求原样转发。
多订阅账号池按优先级使用多个订阅。某个账号本周额度用完，当前请求自动换下一个账号重放，客户端察觉不到；限流与凭据异常分别短时冷却，窗口重置后自动回到高优先级账号。
账号状态自检冷却状态在重启后保留，调整账号顺序、解除冷却都不用重启。查询额度时顺带校正：窗口已重置的提前放回，已触顶的提前停用；免费套餐的账号自动跳过。
账号管理工具导入、分离、排序、手动停用与恢复、备份与还原；登录新账号前先分离，避免 codex login 吊销正在服务的会话。同一文件换了账号会被识别出来，不会悄悄换人服务。
模型目录按本机 Codex CLI 的版本号向后端拉取可用模型、上下文窗口与推理强度，缓存一小时，拉取失败时沿用上一份。
超长上下文兜底后端拒绝超出窗口的提示词时，先换一个缓存亲和 key 重试，再切到长上下文模型，其他拒绝原样返回。
推理链跨轮回传上游返回的加密推理内容随助手消息带回客户端，下一轮原样送回，模型能接着上一轮的思路往下做，而不是每轮从头推理。可用 CODEX_REASONING_REPLAY=off 关闭。
稳定的提示词前缀对话中途插入的 system 消息留在原位，作为 developer 消息发送，不再并进开头的指令。客户端追加提示时前缀不变，上游缓存照常命中。
出图与搜索gpt-image-2 文生图与参考图编辑走同一订阅，一次最多 4 张；网页搜索支持域名过滤并带回来源链接；Codex 0.158 起的独立搜索接口 /v1/alpha/search 直接转发。
额度查询直接读取订阅的周窗口用量、重置时间与额外额度，缓存 30 秒。

自己部署

需要 Python 3.12、一台能访问 chatgpt.com 的机器，以及至少一个已用 codex login 登录过的 ChatGPT 订阅。

git clone https://github.com/bobmcmxciv/codex-bridge
cd codex-bridge
pip install -r requirements.txt
cp .env.example .env                 # 至少改掉 CODEX_BRIDGE_TOKEN
python manage_accounts.py detach     # 把 ~/.codex/auth.json 收进账号池
python codex_bridge.py               # 默认监听 127.0.0.1:8902

客户端把 Base URL 设成 http://127.0.0.1:8902/v1，API Key 填 CODEX_BRIDGE_TOKEN 的值。 要加第二个账号，先 detach 再 codex login，然后 manage_accounts.py import --id 名字： codex login 会在 OpenAI 那边吊销 auth.json 里原有的会话，不先分离就会丢掉正在服务的账号。

环境变量作用
CODEX_BRIDGE_TOKEN客户端访问 bridge 用的共享密钥
CODEX_BRIDGE_HOST / CODEX_BRIDGE_PORT监听地址，默认 127.0.0.1:8902；不建议直接对公网开放
CODEX_MODEL默认模型，客户端没指定或指定了不认识的名字时使用
CODEX_MODEL_LONG提示词超出默认模型窗口时改用的长上下文模型
CODEX_REASONING_EFFORT默认推理强度
CODEX_CLI_PATH本机 Codex CLI 路径，用它的版本号拉取模型目录
CODEX_HOMECodex 凭据目录，以系统服务运行时需要显式指定

接口

以下路径都挂在 https://cx2cc.bobmcmxciv.xin/api 下。Key 放在 x-api-key 或 Authorization: Bearer 请求头里，两种写法等价。OpenAI 协议的接口另有 /openai/v1/… 别名。

接口协议用途需要的权限范围

Key 与权限

Key 由控制台账号创建。控制台有三种角色：

角色能做什么
管理员全部权限：管理所有 Key、授予账号池范围、管理控制台账号、修改计量设置、查看上游账号池
Key 管理员创建 API Key；只看得到、管得了自己创建的 Key 及其审计记录
审计员只读查看全部 Key、调用审计、操作日志与上游状态，不能创建或修改
Key 持有人在控制台用自己的 Key 登录，只看这把 Key 的用量、调用记录和操作记录
一人一 Key。 共用 Key 意味着分不清谁用了多少、泄露后只能全员一起换。每人（或每台机器）单独一把， 用量和审计按 Key 汇总，停用或轮换只影响那一个人。

常见错误

状态码含义处理
401没带 Key、Key 无效、已停用、已过期、已吊销，或是轮换前的旧值检查客户端配置里的 Key；确认没有旧的 ANTHROPIC_API_KEY 盖过新值；找管理员确认 Key 状态
403这把 Key 没有该接口的权限范围，或模型不在白名单里换用允许的模型，或请管理员调整 Key 的权限
429超出每分钟请求数、并发数、每日或近 7 日额度按 Retry-After 等待；需要更高额度找管理员
400请求了服务端不认识的模型名从 /api/v1/models 里选模型名
502入口连不上后面的 cx2cc稍后重试；持续出现请联系管理员

每个响应都带 X-Cx2cc-Request-Id 请求头。反馈问题时附上它，管理员能在调用审计里直接定位到那一次请求。

cx2cc-connect（旧接入方式）
